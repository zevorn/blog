## What Ownership Is

Ownership is a set of rules Rust uses to manage memory. By checking the legality of a program's memory use at compile time, Rust avoids runtime memory-safety problems.

**Advantages of ownership:**
1. Zero runtime overhead, so performance is unaffected;

**Drawbacks in my view:**
1. The learning curve is a little steeper, and as program complexity increases, it takes more mental effort.

### Ownership Principles

**The basic rules of ownership:**
1. Every value in Rust has a variable that owns it; that variable is called the value's owner;
2. A value can be owned by only one variable, or in other words, a value can have only one owner;
3. When the owner (variable) goes out of scope, the value is dropped (drop is called automatically).

Understanding the stack and heap in Rust helps deepen your understanding of ownership.

### Data Interaction Behind Variable Bindings

1. For primitive types (stored on the stack), Rust automatically copies them;
2. Otherwise, they cannot be copied automatically (for example, String).

**Rust's strategy for avoiding double free:**
For complex types (made up of a heap pointer stored on the stack plus other fields), such as String, when ownership is transferred, the old owner becomes invalid, so it will not be dropped when it goes out of scope.

**Rust move:**
Unlike a shallow copy in other languages, once ownership moves, the old owner becomes invalid.

**Rust clone:**
First, Rust never automatically creates a "deep copy" of data. Therefore, any automatic copy is not a deep copy and can be considered to have a relatively small impact on runtime performance.

If we really need to deep-copy the heap data inside a String rather than just the stack data, we can use a method called clone.
```rust
let s1 = String::from("hello");
let s2 = s1.clone();

println!("s1 = {}, s2 = {}", s1, s2);
```
This code runs normally, which shows that s2 really copied all of s1's data.

**Rust copy (shallow copy):**
A shallow copy happens only on the stack, so it is very fast and is everywhere in everyday programming.

```rust
let x = 5;
let y = x;
println!("x = {}, y = {}", x, y);
```

But this code seems to contradict what we just learned: we did not call clone, yet it still behaves like a deep copy — no ownership error is reported.

The reason is that primitive types such as integers have a compile-time-known size and are stored on the stack, so copying their actual values is fast. That means there is no reason to invalidate x after creating y (both x and y remain valid). In other words, there is no deep-vs-shallow-copy distinction here, so calling clone would not differ from the usual shallow copy; we can ignore it (you can think of it as a deep copy on the stack).

**Rust Copy:**
Rust has a trait called Copy that can be used for stack-allocated types such as integers. If a type implements Copy, an old variable remains usable after being assigned to another variable; the assignment itself is the copy.

So which types are Copy? You can check the documentation for a given type, but here is a general rule:

**Any combination of primitive types that does not require heap allocation or some other form of resource allocation can implement Copy.**

Here are some types that can implement Copy:
1. All integer types, such as u32;
2. Boolean values, bool, whose values are true and false;
3. All floating-point types, such as f64;
4. Character type, char;
5. Tuples, but only when all of their element types are also Copy, such as (i32, i32);
6. Immutable references &T. Note: mutable references &mut T cannot implement Copy.

### Passing Values to and Returning from Functions

Passing a value to a function also causes a move or a copy, just like a let statement. The following code demonstrates the rules of ownership and scope:

```rust
fn main() {
    let s = String::from("hello");  // s enters scope

    takes_ownership(s);             // s's value moves into the function ...
                                    // ... so it is no longer valid here

    let x = 5;                      // x enters scope

    makes_copy(x);                  // x would move into the function,
                                    // but i32 implements Copy, so x can still be used later

} // Here x goes out of scope first, then s. But because s's value was moved,
  // nothing special happens.

fn takes_ownership(some_string: String) { // some_string enters scope
    println!("{}", some_string);
} // Here some_string goes out of scope and the `drop` method is called. The occupied memory is freed.

fn makes_copy(some_integer: i32) { // some_integer enters scope
    println!("{}", some_integer);
} // Here some_integer goes out of scope. Nothing special happens.
```
You can try using s again after takes_ownership and see what error you get. For example, add a line like println!("Using s after moving it into the function: {}", s);.

Likewise, return values also have ownership, for example:
```rust
fn main() {
    let s1 = gives_ownership();         // gives_ownership returns its value
                                        // to s1

    let s2 = String::from("hello");     // s2 enters scope

    let s3 = takes_and_gives_back(s2);  // s2 is moved into
                                        // takes_and_gives_back,
                                        // which also returns the value to s3
} // Here s3 goes out of scope and is dropped. s2 also goes out of scope, but it has been moved,
  // so nothing happens. s1 goes out of scope and is dropped.

fn gives_ownership() -> String {             // gives_ownership returns the value to
                                             // the function that called it

    let some_string = String::from("hello"); // some_string enters scope.

    some_string                              // returns some_string and moves it out to the caller
}

// takes_and_gives_back takes a String and returns that value
fn takes_and_gives_back(a_string: String) -> String { // a_string enters scope

    a_string  // returns a_string and moves it out to the caller
}
```

Ownership is powerful and avoids memory unsafety, but it also brings a new annoyance: always passing a value around just to use it. Passing a value into a function often means you also have to pass it back out, which makes the language verbose. Fortunately, Rust provides new features to solve this problem.
